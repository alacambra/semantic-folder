# Iteration 10: YAML-to-JSON Migration for Copilot Indexability

## Objective

Migrate the folder description format from YAML (`folder_description.yaml`) to JSON (`folder_description.json`) and add a root-level index file (`onedrive_index.json`) so that Microsoft 365 Copilot's semantic index can discover and cite folder metadata. The document record schema (envelope + facts) stays the same — only the serialization format changes.

## Motivation

### Business Driver

Microsoft 365 Copilot's semantic index does NOT index `.yaml` or `.md` files. It only indexes a specific set of file types, which includes `.json`. The Datamantics Admin Assistant GPT currently hallucinates folder paths because it cannot find or read the `folder_description.yaml` files. Additionally, there is no root-level index telling the copilot which folders actually exist — it must guess based on abstract descriptions in the system prompt.

### How This Fulfills It

This iteration changes the output format from YAML to JSON (which IS indexed by Microsoft 365) and introduces a root-level `onedrive_index.json` that serves as the copilot's table of contents. After this iteration:

- All `folder_description.json` files will be indexed by Microsoft Search within 24-48h
- The copilot can discover all folders via `onedrive_index.json`
- The copilot system prompt can reference real data instead of abstract folder structures

### D1: Replace YAML serialization with JSON in `models.py`

**Remove:**

**Add:**

```python
@dataclass
class CategoryBreakdown:
    """Aggregated count and total for a category."""
    count: int
    total: float

@dataclass
class Overview:
    """Aggregated statistics for a folder's documents."""
    document_count: int
    date_range: str                           # "YYYY-MM-DD to YYYY-MM-DD" or ""
    types_present: list[str]                  # sorted unique doc_types
    total_amount_eur: float                   # sum of facts.amount where facts.currency == "EUR"
    has_action_items: bool                    # always False (no action tracking)
    by_expense_category: dict[str, CategoryBreakdown]  # keyed by facts.expense_category
    by_country: dict[str, CategoryBreakdown]            # keyed by facts.country
```

```python
class FolderDescription:
    folder_path: str
    folder_type: str
    documents: list[DocumentRecord]
    updated_at: str = ""
    period: str | None = None                 # e.g. "2026-01", inferred or None

    def to_json(self) -> str:
        """Serialize to indented JSON string."""

    def _build_overview(self) -> dict[str, object]:
        """Compute overview from documents list."""

    def _build_documents_list(self) -> list[dict[str, object]]:
        """Build list of plain dicts from document records (same logic, no _FlowSequenceList)."""
```

- `to_json()` uses `json.dumps(data, indent=2, ensure_ascii=False)` + trailing newline
- `_build_overview()` iterates documents, extracts `facts.amount`/`facts.currency`/`facts.expense_category`/`facts.country`, computes aggregations
- `_build_documents_list()` same as current but returns plain `list` for tags (no `_FlowSequenceList`)
- `facts` still omitted from document record when empty (same as current behavior)
- `period` included in `folder` block only when not None
- `period` derivation rule: `generate_description()` infers from the documents' dates — if all non-empty dates share the same `YYYY-MM`, use that as period; otherwise `None`
- `overview.total_amount_eur`: sum `facts.amount` only where `facts.currency == "EUR"`. Missing `currency` or non-EUR → skip (contribute 0.0, no conversion)

JSON output structure:

```json
{
  "folder": {
    "path": "...",
    "type": "...",
    "period": "2026-01",
    "updated_at": "YYYY-MM-DD"
  },
  "overview": {
    "document_count": 17,
    "date_range": "2026-01-16 to 2026-02-02",
    "types_present": ["receipt", "invoice-incoming"],
    "total_amount_eur": 498.29,
    "has_action_items": false,
    "by_expense_category": {
      "travel": {"count": 9, "total": 278.53}
    },
    "by_country": {
      "DE": {"count": 5, "total": 196.07}
    }
  },
  "documents": [...]
}
```

### D5: Root index generation (`onedrive_index.json`)

Add `update_index()` method to `FolderProcessor` that regenerates the root index after each `process_delta()` run.

**Approach:** Use the Graph API search endpoint to find all `folder_description.json` files:

```text
GET /users/{drive_user}/drive/root/search(q='folder_description.json')
```

For each result, download and parse the JSON to extract `folder` and `overview` blocks, then assemble the index.

**Method signature:**

```python
def update_index(self) -> None:
    """Search for all folder_description.json files, build index, upload."""
```

**Call site:** At the end of `process_delta()`, after all `upload_description()` calls and before `save_delta_token()`.

**Config additions:**

- `AppConfig.index_filename: str = "onedrive_index.json"` — configurable via `SF_INDEX_FILENAME`
- `AppConfig.index_owner: str = "Datamantics UG (Albert Lacambra Basil)"` — configurable via `SF_INDEX_OWNER`

**Index structure:**

```json
{
  "schema_version": "1.0",
  "updated_at": "YYYY-MM-DD",
  "owner": "Datamantics UG (Albert Lacambra Basil)",
  "folders": [
    {
      "path": "/drive/root:/oficina/steuerberater/2026/gener",
      "type": "business-expenses",
      "period": "2026-01",
      "document_count": 17,
      "total_eur": 498.29
    }
  ]
}
```

**Upload path:** `PUT /users/{drive_user}/drive/root:/{index_filename}:/content`

**Pagination:** Follow `@odata.nextLink` until exhausted (same pattern as delta API pagination).

**Constructor changes:** `FolderProcessor.__init__` gains `index_filename: str = "onedrive_index.json"` and `index_owner: str = "Datamantics UG (Albert Lacambra Basil)"` parameters. `folder_processor_from_config` passes `config.index_filename` and `config.index_owner`.

Files: `src/semantic_folder/orchestration/processor.py`, `src/semantic_folder/config.py`

### D9: Legacy cleanup endpoint — delete obsolete `.yaml` and `.md` description files

Add a manually-triggered HTTP endpoint (`POST /cleanup`) that scans all OneDrive folders and deletes legacy `folder_description.yaml` and `folder_description.md` files.

**GraphClient addition:**

```python
def delete(self, path: str) -> None:
    """Perform an authenticated DELETE request to the Graph API."""
```

Same pattern as `put_content` but with `method="DELETE"` and no request body.

**FolderProcessor method:**

```python
def cleanup_legacy_descriptions(self, *, dry_run: bool = False) -> list[str]:
    """Find and delete all legacy folder_description.yaml/.md files.

    Uses Graph search API to find files, then deletes each via
    DELETE /users/{drive_user}/drive/items/{item_id}.

    Args:
        dry_run: If True, return paths without deleting.

    Returns:
        List of deleted (or would-be-deleted) file paths.
    """
```

**Approach:** Use search API to find legacy files:

```text
GET /users/{drive_user}/drive/root/search(q='folder_description.yaml')
GET /users/{drive_user}/drive/root/search(q='folder_description.md')
```

Filter results to exact filename matches (search may return partial matches). Delete via `DELETE /users/{drive_user}/drive/items/{item_id}`.

**HTTP endpoint:**

```python
@bp.route(route="cleanup", methods=["POST"], auth_level=func.AuthLevel.FUNCTION)
def cleanup_legacy(req: func.HttpRequest) -> func.HttpResponse:
    """Delete legacy .yaml and .md folder description files."""
```

- Query parameter `dry_run=true` activates dry-run mode
- Response: `{"status": "ok", "deleted": ["path1", ...], "deleted_count": N, "dry_run": false}`
- Log each deletion at INFO level

Files: `src/semantic_folder/functions/http_trigger.py`, `src/semantic_folder/orchestration/processor.py`, `src/semantic_folder/graph/client.py`
